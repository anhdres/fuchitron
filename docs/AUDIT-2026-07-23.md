# Fuchitron — Deep audit (2026-07-23)

**Goal:** ship a more polished version of the app before sharing it more widely. This is NOT a generic checklist: I read `index.html`, `live.html`, `spectate.html`, `app.js`, `i18n.js`, `styles.css`, `sw.js`, `manifest.json` and `vercel.json` in full. What follows are real bugs with line numbers, grouped by severity, with a suggested fix.

**TL;DR (must-fix):**
1. The clock loses time if you reload the page while the match is running (drift).
2. The spectator view has 3 bugs that ruin the experience: it hardcodes 45', it never receives the goal list, and it merges the result into a single state instead of honoring the live view.
3. There's hardcoded English text that leaks through when the language isn't English (especially the "Spectate link" button and the share alert).
4. Small mobile (<360px) breaks legibility: the scoreboard drops to a single column and the numbers end up huge but isolated.
5. Accessibility is almost nonexistent: no keyboard handlers, no live region for goals, no focus trap in dialogs, critical icons have no label.
6. The PWA cache doesn't include `/live/`, `/s/`, or `og-image.png`.

---

## 🔴 CRITICAL (break functionality or visible UX)

### C1. Clock loses time on reload (timer drift)
**File:** `src/app.js:1060`
**Symptom:** If the match is running and you reload the page (or close the tab and come back), the clock restarts with a tick that only adds seconds instead of recomputing from `matchStartTS`. Result: the clock falls behind by however long the page was closed.

```js
// app.js:1060 — "if (state.running)" block at the end of the file
if (state.running) {
  tick = setInterval(() => {
    state.halfSeconds++;            // ❌ drift — does not consult matchStartTS
    els.clock.textContent = clockTxt(state.halfSeconds);
    ...
  }, 1000);
}
```

**Fix:** Reuse the same block from `toggleClock()` (lines 380-389) that does recompute from `matchStartTS`. In init, if `state.running`, mount a tick that calls `getElapsedSeconds()` and assigns `state.halfSeconds = elapsed`.

---

### C2. Spectator hardcodes 45' and doesn't show the live state
**File:** `src/live.html:108`
```js
const target = 45 * 60;
const over = (m.half_seconds || 0) - target;
```
**Symptom:** If the host plays 10', 15' or 30' matches, the "+1" never appears in the live view even though the host sees it. The target should come from the payload, not be hardcoded.

**Fix:** Add `period_minutes` to the Supabase payload (see C3) and read it in `live.html`. If missing, fall back to 45 with a `console.warn`.

**Sub-issue (same file, `renderMatch`):** the line
`periodLabel.textContent = !matchStarted ? 'POR COMENZAR' : (half === 1 ? '1T' : ...)`
shows "POR COMENZAR" if the host hasn't pressed Start yet. That's fine, but it should be localized (it's hardcoded in Spanish now — if the host opened share in English, the spectator sees Spanish).

---

### C3. Payload to Supabase never sends the goals or the period
**File:** `src/app.js:883-890` (POST) and `919-927` (PATCH)
```js
const match = {
  team_a: state.teamA || 'Local',
  team_b: state.teamB || 'Visitante',
  score_a: ...,
  score_b: ...,
  current_half: state.currentHalf,
  half_seconds: state.halfSeconds,
  running: state.running,
  finished: state.finished,
  match_start_ts: state.matchStartTS ? String(state.matchStartTS) : null,
};
```
**Symptom:** The spectator sees the big score but the timeline in `live.html` (id `goalsList`) stays empty even when the host has scored goals. Also, `period_minutes` is not received (cause of bug C2).

**Fix:** Add to the payload:
```js
goals: state.goals.map(g => ({ ...g, ts: Date.now() })),  // jsonb in Supabase
period_minutes: state.periodMinutes,
language: state.lang,                                     // to localize the spectator
```
And in `live.html`, populate `#goalsList` from `m.goals`.

### C4. "Spectate link" button + alert hardcoded in English
**File:** `src/app.js:870, 902-908`
```js
<button id="createSpectateBtn" class="share-dialog-btn ghost">
  ...
  <span>Spectate link</span>     // ❌ hardcoded
</button>

const shareText = `🔥 Follow this match live: ${spectateUrl}`;  // ❌
if (navigator.clipboard) {
  await navigator.clipboard.writeText(shareText);
  alert('Spectate link copied to clipboard!');  // ❌
} else {
  prompt('Share this link:', spectateUrl);  // ❌
}
```
**Symptom:** When the user has the app in Spanish, Portuguese, or Chinese, the button still says "Spectate link". The toast too.

**Fix:** Add 3 keys to `i18n.js` in 7 languages:
```js
es: { spectateLink: 'Link para seguir en vivo', spectateToast: '¡Link copiado!', spectatePrompt: 'Compartí este link:' }
```
And replace the literals with `t('spectateLink')` etc.

### C5. "Spectate link" button always creates a new link
**File:** `src/app.js:879-908`
**Symptom:** Every time you tap the button, a new code is generated and another POST is done. If you want to re-share the same match, you generate 2 different codes (one stays orphaned in Supabase). Worse: if you reload the page with a previous `state.spectateCode`, that code stays in localStorage but the button "creates another" instead of showing the existing one.

**Fix:** Before the POST, check if `state.spectateCode` already exists:
```js
els.createSpectateBtn.addEventListener('click', async () => {
  if (state.spectateCode) {
    const url = `${location.origin}/live/${state.spectateCode}`;
    await navigator.clipboard.writeText(`🔥 ${t('spectateToast')}: ${url}`);
    return;
  }
  // ... existing create code
});
```
And show the active code somewhere in the dialog (e.g. small text above the button: "Sharing as XXXXXX — Reset").

### C6. SW doesn't cache `/live/`, `/s/` or `og-image.png`
**File:** `src/sw.js:5-13`
**Symptom:** If you're on the field with no signal and open a spectate link, it doesn't load (not even the empty page with "EN VIVO"). The manifest is also not included but the first fetch caches it anyway. Worse: if you save the "offline" link (installing the PWA), the home works but the spectate does not.

**Fix:** Add to `ASSETS`:
```js
'./live.html',
'./spectate.html',
'./manifest.json',
'./icons/og-image.png',
```
And update the `fetch` handler so that `/live/:code` and `/s/:code` also serve the corresponding cached page as a fallback.

## 🟠 MAJOR (visible but not breaking)

### M1. Mobile <360px breaks layout
**File:** `src/styles.css:466-470`
```css
@media (max-width: 360px) {
  .scoreboard, .goal-buttons-outside, .share-grid { grid-template-columns: 1fr; }
  .vs-chip { display: none; }
}
```
**Symptom:** On a 320px iPhone SE (or a cheap 360 Android), the scoreboard drops to a single column with one card per line and the rival team goes below the local score instead of next to it. On the field, that's exactly the moment you can't miss.

**Fix:** Don't drop the grid to 1fr at that breakpoint. Better:
- Reduce `score-number` to `clamp(56px, 22vw, 88px)`
- Lower team-panel `min-height` to 120
- Accept the VS being small but visible (`font-size: 11px`)

Or better: keep 2 columns always (narrower) and let numbers scale with `clamp`.

---

### M2. Dual storage with no migration
**File:** `src/app.js:80-86`
```js
const save = () => {
  if (state.spectateCode) localStorage.setItem('fuchitron_spectate_code', state.spectateCode);
  localStorage.setItem('fuchitron_v4', JSON.stringify(state));  // v4 without docs
};
```
**Symptom:** The `_v4` suffix suggests there was v1/v2/v3. There's no migration code, so old users get clean defaults on future upgrades. Plus splitting into two keys is unnecessary and prone to drift.

**Fix:** A single `fuchitron_state` key with a `version: 4` field inside. A `loadState()` function that, on seeing an old version, either migrates or discards.

### M3. Score redundant with goals
**File:** `src/app.js:23-24, 260-261`
```js
scoreA: 0,
scoreB: 0,
...
els.scoreA.textContent = (state.goals || []).filter(g => g.side === 'A').length;
```
**Symptom:** `state.scoreA`/`scoreB` are never updated in `addGoal`/`deleteGoalById` (those only modify `state.goals`). The render recalculates them, so it works visually, but they're zombie fields. If anyone in the future reads `state.scoreA` directly (e.g. for the share image), they'll read 0.

**Fix:** Remove `scoreA`/`scoreB` from state, or use them as cache. If you keep them, also update them in `addGoal`/`deleteGoalById`.

---

### M4. `goalMinute()` returns 1 even when it was instant
**File:** `src/app.js:298`
```js
function goalMinute() {
  if (!state.matchStarted) return 0;
  return Math.max(1, Math.floor(getElapsedSeconds() / 60));
}
```
**Symptom:** If you score at 10 seconds into the half, the timeline says `1'`. Some users expect `0'` (FIFA style) or `"-"` (statistic style).

**Product decision:** keeping `Math.max(1, ...)` is fine for legibility (field, quick glance at the phone), but the share text shows the same thing. Consistent, OK. Leave it. (Documented, not a bug.)

### M5. No confirmation when deleting a goal from the timeline
**File:** `src/app.js:344-348`
```js
function deleteGoalById(id) {
  const idx = state.goals.findIndex(g => g.id === id);
  if (idx < 0) return;
  state.goals.splice(idx, 1);
  save(); render();
}
```
**Symptom:** Tap the X on the goal and it's deleted without asking. On the field, with sweaty fingers, it's an accidental tap and the goal is lost. There is an "undo last" but the user has to realize.

**Fix:** Add `if (!window.confirm(t('confirmDeleteGoal'))) return;` with a message in 7 languages. Better alternative: implement undo as a snackbar with 5s timeout — cleaner, doesn't interrupt flow.

### M6. Reload with match in 2T loses position
**File:** `src/app.js` (not present)
**Symptom:** `matchStartTS` is rewritten in `nextPeriod()` with `Date.now()`, so the time relative to 2T is correct. But there's no `halfStartTS` to distinguish. In practice it works because `getElapsedSeconds()` is called from the running tick.

**Sub-issue:** If you reload the page with `state.running=true`, the init mounts a tick that DOES use `getElapsedSeconds()`... but it doesn't (see C1). There's one init block and another running one — the init one is wrong.

### M7. Possible collisions in `generateMatchCode`
**File:** `src/app.js:912-917`
```js
function generateMatchCode() {
  const chars = 'ABCDEFGHJKLMNPQRSTUVWXYZ23456789';  // 32 chars
  let code = '';
  for (let i = 0; i < 6; i++) code += chars[Math.floor(Math.random() * chars.length)];
  return code;
}
```
**Symptom:** 32⁶ = ~1.07 billion. Birthday paradox: 50% collision at ~37k active codes. For an amateur football app with dozens of matches per weekend, it's fine. But the POST to Supabase doesn't check `409 Conflict` if the code already exists — it silently creates a duplicate.

**Fix:** Catch on the POST:
```js
if (!r.ok) {
  if (r.status === 409) { /* retry with new code */ }
  else alert('Error creating link 😕');
}
```

### M8. live.html doesn't include i18n or VS styling
**File:** `src/live.html:80`
```js
periodLabel.textContent = !matchStarted ? 'POR COMENZAR' : ...;
```
**Symptom:** The spectator sees "POR COMENZAR", "HOME", "AWAY", "EN VIVO" hardcoded in Spanish, regardless of the language the host chose (the share text respects the host's language, but the spectator UI doesn't).

**Fix:** Inline minimal `t()` in `live.html`, or pass the language via URL (`/live/ABCDEF?lang=es`) when the host shares the link.

## 🟡 MINOR (cleanup, accessibility, PWA, performance)

### m1. Accessibility is almost nonexistent
- **No keyboard handlers.** You can't add a goal with the keyboard (space, enter, arrows). On the field it's not critical, but someone with a hand injury needs it.
- **Dialog without focus trap.** Open settings, tab, exit the dialog and keep tabbing the background (which shouldn't be focusable).
- **No `aria-live` for goals.** Screen readers don't announce score changes. Add `<div id="scoreA" aria-live="polite" aria-atomic="true">`.
- **Goal banner (`#goalBanner`) is not accessible.** It's decorative but a screen reader still reads it. Add `aria-hidden="true"` or `role="presentation"`.
- **Icon-only buttons with no visible label.** The "delete goal" button has `font-size: 0` and shows an ✕ via CSS. The screen reader doesn't know what it is. Add `aria-label="Delete goal"`.

### m2. `alert()` blocks the flow
- Confirming reset / 1T / goal deletion: all use native `alert()`/`confirm()`. On iOS Safari they don't render well with the dialog backdrop.
- **Fix:** Use a mini-dialog (`<dialog>` or a custom modal) or a toast with an "Undo" action.

### m3. No "offline" indicator
- The SW caches assets but the UI never says "You're offline". On the field with no signal, the user doesn't know if the goal was saved.
- **Fix:** `online`/`offline` listener + persistent banner when offline.

### m4. Share image canvas redraws on every `renderSharePreview`
- It's called on the 3 checkboxes' `change`. If the user toggles "Include date" + "Text format" quickly, 3 canvases of 1080x1080 are generated synchronously. Not a problem (takes <50ms), but could be debounced.
- **Minor fix:** wrap in `requestAnimationFrame` or debounce 100ms.

### m5. Material Symbols loads but is barely used
- `Material+Symbols+Outlined` loads the full font (~200KB) for just 5 icons. **Fix:** self-host or change to inline SVG. Fuchitron's iconography is tiny (timer_play, pause, restart, settings, share, close, add_circle, link, content_copy, download, fullscreen, timer_off, share, close) — 14 icons. Inline SVG would be <5KB.

### m6. Fonts block render
- 4 Google Fonts families loaded with `display=swap` (not bad), but `.clock` and `.score-number` (the most critical) use Space Grotesk. On the first paint they show fallback (Lexend, system-ui) → re-render with the real one. Creates a visible "flash" on cold start.
- **Fix:** `<link rel="preload" as="font" href="...">` for the critical ones, or inline the most-used font.

### m7. `setupInstallPrompt` can show button on iOS
- `els.installApp.hidden = false` fires on the `beforeinstallprompt` listener. iOS doesn't fire that event (Android/Chrome only). But the button could be shown if `deferredInstallPrompt` existed and the user dismissed it. Not a critical bug because the iOS hint is separate, but it could confuse.
- **Fix:** check platform before showing the button.

### m8. `els.periodMinutes = $('periodMinutes')` doesn't exist
- Line 48: reference to an id that's not in the HTML. `els.periodMinutes` is `undefined` and never read. Minor cleanup.

### m9. Verify safe visualization on iPhone with notch
- `.topbar` has `padding: 0 14px` but no `padding-top: env(safe-area-inset-top)`. The logo and title can be below the notch in portrait.
- **Fix:** `padding-top: max(0px, env(safe-area-inset-top))` or `padding: env(safe-area-inset-top) 14px 0;` on `.topbar`.

### m10. Canvas date for `zh` hardcodes `zh-CN`
- `src/app.js:466` and `src/app.js:660`:
  ```js
  new Date().toLocaleDateString(state.lang === 'zh' ? 'zh-CN' : state.lang, ...)
  ```
- If you ever add `zh-TW`, you have to touch two places. Move to a `formatDate(lang)` helper.

### m11. backup.sh not versioned
- `scripts/backup.sh` is not called automatically before each deploy. There's no pre-deploy hook.
- **Fix:** add to the "before each git push" flow (could be an alias or a pre-commit hook).

**Block A — Critical bugs (must-have):**
1. C1: Timer drift on reload (simple fix, ~10 lines)
2. C2 + C3: Spectator receives `goals` + `period_minutes` from the payload
3. C4: i18n of the spectate link button + alert

**Block B — Visible polish (should-have):**

7. M5: Confirmation/snackbar when deleting a goal
8. m1 (partial): aria-live on scores, aria-label on delete, safe-area on topbar

**Block C — Nice to have:**
10. m5: Replace Material Symbols with inline SVG (200KB → 5KB)
11. m3: Offline indicator

**Estimated work:**
- Block A: one short session (2-3h)
- Block B: one session (2-4h)
- Block C: optional, depending on how much polish is wanted

**My honest recommendation:** do Block A no matter what (the spectator bugs are the ugliest because that's the first thing the people who don't have the app will see). Block B is what makes the difference between "usable" and "shareable without apologizing". Block C is perf and a11y but doesn't show up until someone looks for it.
