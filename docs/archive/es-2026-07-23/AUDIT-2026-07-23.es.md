# Fuchitron — Auditoría profunda (2026-07-23)

**Objetivo:** dejar la app lista para compartir más en serio. Esto NO es una lista
genérica: leí `index.html`, `live.html`, `spectate.html`, `app.js`, `i18n.js`,
`styles.css`, `sw.js`, `manifest.json` y `vercel.json` completos. Lo que sigue son
bugs reales con línea y todo, agrupados por severidad, con fix sugerido.

**TL;DR (qué hay que arreglar sí o sí):**
1. Cronómetro pierde tiempo si recargás la página con el partido en curso (drift).
2. El modo espectador tiene 3 bugs que rompen la experiencia: hardcodea 45', nunca
   recibe la lista de goles, y se mezcla el resultado en uno solo en vez de respetar
   el parcial.
3. Hay texto hardcodeado en inglés que se filtra cuando el idioma no es inglés
   (especialmente el botón "Spectate link" y todo el alert de compartir).
4. Mobile chico (<360px) se rompe la legibilidad: el scoreboard pasa a 1 columna y
   los números quedan enormes pero aislados.
5. Accesibilidad casi nula: no hay keyboard handlers, no hay live region para los
   goles, no hay focus trap en los dialogs, los íconos críticos no tienen label.
6. La caché PWA no incluye `/live/`, `/s/`, ni `og-image.png`.

## 🔴 CRÍTICOS (rompen funcionalidad o experiencia visible)

### C1. Cronómetro pierde tiempo al recargar (timer drift)
**Archivo:** `src/app.js:1060`
**Síntoma:** Si el partido está corriendo y recargás la página (o se cierra la
pestaña y volvés), el reloj arranca con un tick que sólo suma segundos en vez de
recomputar desde `matchStartTS`. Resultado: el cronómetro queda atrasado por todo
el tiempo que la página estuvo cerrada.

```js
// app.js:1060 — bloque "if (state.running)" al final del archivo
if (state.running) {
  tick = setInterval(() => {
    state.halfSeconds++;            // ❌ drift — no consulta matchStartTS
    els.clock.textContent = clockTxt(state.halfSeconds);
    ...
  }, 1000);
}
```

**Fix:** Reusar el mismo bloque de `toggleClock()` (líneas 380-389) que sí
recomputa desde `matchStartTS`. Es decir, en el init si `state.running`, montar
un tick que llame a `getElapsedSeconds()` y haga `state.halfSeconds = elapsed`.

### C2. Espectador hardcodea 45' y no muestra el parcial
**Archivo:** `src/live.html:108`
```js
const target = 45 * 60;
const over = (m.half_seconds || 0) - target;
```
**Síntoma:** Si el dueño del partido juega 10', 15' o 30', el "+1" nunca aparece
en el live aunque el host sí lo vea. Además, el target debería venir del payload,
no estar hardcodeado.

**Fix:** Agregar `period_minutes` al payload de Supabase (ver C3) y leerlo en
`live.html`. Si no viene, fallback a 45 con un console.warn.

**Sub-issue (mismo archivo, `renderMatch`):** la línea
`periodLabel.textContent = !matchStarted ? 'POR COMENZAR' : (half === 1 ? '1T' : ...)`
muestra "POR COMENZAR" si el local aún no apretó Iniciar. Eso está bien, pero
debería localizarse (ahora está hardcoded en ES — si el local abrió el share en
EN, el espectador ve español).

### C3. Payload a Supabase nunca manda los goles ni el período
**Archivo:** `src/app.js:883-890` (POST) y `919-927` (PATCH)
```js
const match = {
  team_a: state.teamA || 'Local',
  team_b: state.teamB || 'Visitante',
  score_a: ...,
  score_b: ...,
  current_half: state.currentHalf,
  half_seconds: state.halfSeconds,
  running: state.running,
  finished: state.finished,
  match_start_ts: state.matchStartTS ? String(state.matchStartTS) : null,
};
```
**Síntoma:** El espectador ve el score grande pero la timeline de `live.html`
(id `goalsList`) queda vacía aunque el local tenga goles. Además, no recibe
`period_minutes` (causa del bug C2).

**Fix:** Agregar al payload:
```js
goals: state.goals.map(g => ({ ...g, ts: Date.now() })),  // jsonb en Supabase
period_minutes: state.periodMinutes,
language: state.lang,                                     // para localizar el espectador
```
Y en `live.html`, poblar `#goalsList` desde `m.goals`.

### C4. Texto "Spectate link" + alert hardcodeado en inglés
**Archivo:** `src/app.js:870, 902-908`
```js
<button id="createSpectateBtn" class="share-dialog-btn ghost">
  ...
  <span>Spectate link</span>     // ❌ hardcoded
</button>

const shareText = `🔥 Follow this match live: ${spectateUrl}`;  // ❌

  alert('Spectate link copied to clipboard!');  // ❌

```
**Síntoma:** Cuando el usuario tiene la app en español, portugués o chino, el
botón dice "Spectate link" igual. El toast también.

**Fix:** Agregar 3 keys a `i18n.js` en los 7 idiomas:
```js
es: { spectateLink: 'Link para seguir en vivo', spectateToast: '¡Link copiado!', spectatePrompt: 'Compartí este link:' }
```
Y reemplazar los string literales por `t('spectateLink')` etc.

### C5. Botón "Spectate link" crea link nuevo siempre, no reutiliza
**Archivo:** `src/app.js:879-908`
**Síntoma:** Cada vez que tocás el botón, se genera un código nuevo y se hace
otro POST. Si querés volver a compartir el mismo partido, generás 2 códigos
distintos (uno queda huérfano en Supabase). Peor: si recargás la página con un
`state.spectateCode` previo, ese código queda en localStorage pero el botón
"crea otro" en vez de mostrar el existente.

**Fix:** Antes del POST, chequear si `state.spectateCode` ya existe:
```js
els.createSpectateBtn.addEventListener('click', async () => {
  if (state.spectateCode) {
    const url = `${location.origin}/live/${state.spectateCode}`;
    await navigator.clipboard.writeText(`🔥 ${t('spectateToast')}: ${url}`);
    return;
  }
  // ... código de creación actual
});
```
Y mostrar el código activo en algún lugar del dialog (ej. arriba del botón, en
letra chica "Compartiendo como XXXXXX — Reset").

### C6. SW no cachea `/live/`, `/s/` ni `og-image.png`
**Archivo:** `src/sw.js:5-13`
**Síntoma:** Si estás en la cancha sin señal y abrís un link de spectate, no
carga (ni siquiera la página vacía con el "EN VIVO"). El manifest tampoco está
incluido pero igual lo cachea el primer fetch. Más grave: si guardás el link
"offline" (instalando PWA), la home funciona pero el spectate no.

**Fix:** Agregar a `ASSETS`:
```js
'./live.html',
'./spectate.html',
'./manifest.json',
'./icons/og-image.png',
```
Y actualizar el `fetch` handler para que `/live/:code` y `/s/:code` también
sirvan la página correspondiente del cache como fallback.

## 🟠 MAYORES (visibles pero no rompen)

### M1. Mobile <360px rompe layout
**Archivo:** `src/styles.css:466-470`
```css
@media (max-width: 360px) {
  .scoreboard, .goal-buttons-outside, .share-grid { grid-template-columns: 1fr; }
  .vs-chip { display: none; }
}
```
**Síntoma:** En un iPhone SE de 320px (o un Android barato de 360), el scoreboard
pasa a 1 columna con una sola card por línea y la otra debajo. Los números
quedan enormes pero el equipo rival queda debajo del marcador local en vez de al
lado. En la cancha, eso es exactamente el momento donde no podés errarle.

**Fix:** En ese breakpoint NO tirar abajo el grid a 1fr. Mejor:
- Reducir el `score-number` a `clamp(56px, 22vw, 88px)`
- Bajar `min-height` de team-panel a 120
- Aceptar que el VS quede chico pero visible (`font-size: 11px`)

O mejor aún: layout siempre 2 columnas (más estrecho) y dejar que los números
escalen con `clamp`.

### M2. Storage dual sin migración
**Archivo:** `src/app.js:80-86`
```js
const save = () => {
  if (state.spectateCode) localStorage.setItem('fuchitron_spectate_code', state.spectateCode);
  localStorage.setItem('fuchitron_v4', JSON.stringify(state));  // v4 sin docs
```

Función `loadState()` que si ve una versión vieja, intenta migrar o descarta.

```js
scoreA: 0,
```

### M4. `goalMinute()` devuelve 1 aunque haya sido al instante
**Archivo:** `src/app.js:298`
```js
function goalMinute() {
  if (!state.matchStarted) return 0;
  return Math.max(1, Math.floor(getElapsedSeconds() / 60));
}
```
**Síntoma:** Si metés un gol a los 10 segundos del kickoff, el timeline dice
`1'`. Algunos usuarios lo esperan en `0'` (estilo FIFA) o `"-"` (estilo
estadística).

**Decisión de producto:** mantener `Math.max(1, ...)` está bien para legibilidad
(cancha, mirar el celu rápido), pero el share text muestra la misma cosa.
Consistente, OK. Dejarlo. (Lo dejo documentado, no es bug.)

### M5. No hay confirmación al borrar gol desde timeline
**Archivo:** `src/app.js:344-348`
```js
function deleteGoalById(id) {
  const idx = state.goals.findIndex(g => g.id === id);
  if (idx < 0) return;
  state.goals.splice(idx, 1);
  save(); render();
}
```
**Síntoma:** Tocás la X del gol y se borra sin avisar. En la cancha, con dedos

### M7. Posibles colisiones en `generateMatchCode`
**Archivo:** `src/app.js:912-917`
```js
function generateMatchCode() {
  const chars = 'ABCDEFGHJKLMNPQRSTUVWXYZ23456789';  // 32 chars
  let code = '';
  for (let i = 0; i < 6; i++) code += chars[Math.floor(Math.random() * chars.length)];
  return code;
}
```
**Síntoma:** 32⁶ = ~1.07 mil millones. Birthday paradox: 50% de colisión con
~37k códigos activos. Para un app de fútbol amateur donde hay docenas de
partidos por fin de semana, está bien. Pero el POST a Supabase no chequea
`409 Conflict` si el código ya existe — silenciosamente crea un duplicado.

**Fix:** Catch en el POST:
```js
if (!r.ok) {
  if (r.status === 409) { /* retry con nuevo código */ }
  else alert('Error creando link 😕');
}
```

## 🟡 MENORES (limpieza, accesibilidad, PWA, perf)

### m1. Accesibilidad casi nula
- **No hay keyboard handlers.** No podés sumar gol con teclado (espacio, enter,
  flechas). En la cancha no es crítico, pero alguien con lesión en la mano sí lo
  necesita.
- **Dialog sin focus trap.** Abrís settings, tabulás, salís del dialog y seguís
  tabulando el fondo (que no debería ser focusable).
- **No hay `aria-live` para goles.** Screen readers no anuncian el cambio de
  score. Agregar `<div id="scoreA" aria-live="polite" aria-atomic="true">`.
- **Goal banner (`#goalBanner`) no es accesible.** Es decorativo pero igual lo
  lee un screen reader. Agregar `aria-hidden="true"` o `role="presentation"`.
- **Botones con sólo ícono sin label visible.** El botón "delete goal" tiene
  `font-size: 0` y muestra una ✕ por CSS. El screen reader no sabe qué es.
  Agregar `aria-label="Borrar gol"`.

### m2. `alert()` bloquea el flujo
- Confirmar reset / 1T / borrar gol: todos usan `alert()`/`confirm()` nativos del
  browser. En iOS Safari no se ven bien con el backdrop de los dialogs.
- **Fix:** Usar un mini-dialog propio (`<dialog>` o un modal custom) o un toast
  con acción "Deshacer".

### m3. No hay indicador de "offline"
- El SW cachea assets pero la UI nunca avisa "Estás sin conexión". En la
  cancha sin señal, el usuario no sabe si guardó el gol o no.
- **Fix:** Listener `online`/`offline` + banner persistente cuando offline.

### m4. Canvas de share image se redibuja en cada `renderSharePreview`
- Se llama en `change` de los 3 checkboxes. Si el usuario toca "Incluir fecha"
  + "Formato texto" rápido, se generan 3 canvas de 1080x1080 sincrónicamente.
  No es problema (tarda <50ms), pero podría debounce.
- **Fix menor:** wrap en `requestAnimationFrame` o debounce 100ms.

### m5. Material Symbols carga pero no se usa bien
- `Material+Symbols+Outlined` carga la fuente completa (~200KB) sólo por 5
  íconos. **Fix:** self-host o cambiar a SVG inline. La íconografía de Fuchitron
  es chica (timer_play, pause, restart, settings, share, close, add_circle, link,
  content_copy, download, fullscreen, timer_off, share, close) — 14 íconos
  apenas. SVG inline sería <5KB.

### m6. Fonts bloquean render
- 4 families de Google Fonts cargadas con `display=swap` (no está mal), pero
  los `.clock` y `.score-number` (los más críticos) usan Space Grotesk. En el
  primer paint muestran fallback (Lexend, system-ui) → re-render con la real.
  Genera un "flash" visible en cold start.
- **Fix:** `<link rel="preload" as="font" href="...">` para los críticos, o
  inline la fuente más usada.

### m7. `setupInstallPrompt` puede mostrar botón en iOS
- `els.installApp.hidden = false` se dispara en el listener de
  `beforeinstallprompt`. En iOS ese evento no se dispara (es solo Android/Chrome).
  Pero el botón se podría mostrar si `deferredInstallPrompt` existió y después
  el user lo descartó. No es bug crítico porque el hint para iOS está separado,
  pero podría confundir.
- **Fix:** chequear plataforma antes de mostrar el botón.

### m8. `els.periodMinutes = $('periodMinutes')` no existe
- Línea 48: referencia a un id que no está en el HTML. `els.periodMinutes` es
  `undefined` y nunca se lee. Cleanup menor.

### m9. Verificar visualización segura en iPhone con notch
- `.topbar` tiene `padding: 0 14px` pero no `padding-top: env(safe-area-inset-top)`.
  El logo y el título pueden quedar debajo del notch en vertical.
- **Fix:** `padding-top: max(0px, env(safe-area-inset-top))` o usar
  `padding: env(safe-area-inset-top) 14px 0;` en el `.topbar`.

### m10. Canvas date para `zh` hardcodea `zh-CN`
- `src/app.js:466` y `src/app.js:660`:
  ```js
  new Date().toLocaleDateString(state.lang === 'zh' ? 'zh-CN' : state.lang, ...)
  ```
- Si algún día agregás zh-TW, hay que tocar dos lugares. Mover a un helper
  `formatDate(lang)`.

### m11. Backup.sh no versionado
- `scripts/backup.sh` no se llama automáticamente antes de cada deploy.
  Tampoco hay pre-deploy hook.
- **Fix:** agregar al flujo "antes de cada git push" (puede ser un alias o un
  pre-commit hook).
